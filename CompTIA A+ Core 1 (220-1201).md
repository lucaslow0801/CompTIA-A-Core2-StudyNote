# 2.0 Networking

# 2.1 Introduce to IP  (Internet Protocol)

- TCP and UDP
    1. Transported inside of IP
        - Encapsulated by the IP protocol
    2. Two ways to move data from place to place
        - Different features for different applications
    3. OSI Layer 4
        - The transport layer
        - 
    4. Multiplexing
        - Use many different applications at the same time
        - TCP and UDP
- TCP - Transmission Control Protocol
    1. Connection-oriented
        - A formal connection setup and close
        - connection-oriented protocol using a three-way handshake
    2. Reliable delivery
        - Recovery from errors, guarantee data correct
        - Can manage out of order messages or retransmissions
    3. Flow control
        - The receiver can manage how much data is sent
- UDP - User Datagram Protocol
    1. Connectionless
        - No formal open or close to the connection
    2. Unreliable delivery
        - No error recovery
        - No reordering of data or retransmissions
    3. No flow control
        - Sender determines the amount of data transmitted
- Why would you ever use **UDP**
    1. Real-time communication
        - There’s no way to stop and resend the data
        - Time doesn’t stop for your network
    2. Connectionless protocols
        - DHCP (Dynamic Host Configuration Protocol)
        - TFTP (Trivial File Transfer Protocol)
    3. The data might not get through
        - The application keep track and decide what to do
        - It might not do anything
- Communication using **TCP**
    1. Connection-oriented protocols prefer a “return receipt”
        - HTTPS (Hypertext Transfer Protocol Secure)
        - SSH (Secure Shell)
    2. The application doesn’t worry about out of order frames or missing data
        - TCP handles all of the communication overhead
        - The application has one job

# 2.4 DNS Configuration

- Address records (A) (AAAA)
    1. Defines the IP address of host
        - This is the most popular query
    2. A record are for IPv4 addresses
        - Modify the A record to change the host name to IP address resolution
    3. AAA record are for IPv6 addresses
        - The same DNS server, different record
- Canonical name records (CNAME)
    1. A name is an alias of another, canonical name
        - One physical server, Multiple services
    2. The "Nickname" Analogy
        - Imagine you host a website on a server with the IP `104.18.32.10`.
        1. You create an **A Record** for your main site: `example.com`  in `104.18.32.10`.
        2. You create **CNAMEs** for other services:
            ◦ `www.example.com` = `example.com`
            ◦ `shop.example.com` = `example.com`
            ◦ `blog.example.com` = `example.com`
- Mail exchanger record (MX)
    1. Determines the host name for the mail server
        - This isn’t an IP address; it’s a name
- Text record (TXT)
    1. Human-readable text information
        - Originally, these were meant for any human-readable notes, but today they are used for **Security** and **Verification**.
    2. DKIM (DomainKeys Identified Mail)
        - This adds a "digital signature" to your emails so the receiver knows the message wasn't changed while it was being sent.
        - The public key is in the DKIM TXT record
    3. SPF (Sender Policy Framework)
        - This lists which mail servers are *allowed* to send email for your domain. It prevents hackers from pretending to be you (spoofing).
        - Mail servers perform a check to see if incoming mail really did come from authorized host
    
    4.  DMARC (Domain based Message Authentication, Reporting and Conformance)
    
    - If **SPF** and **DKIM** (which live inside TXT records) are the ID cards, **DMARC** is the **Security Guard** who decides what to do if those ID cards are missing or fake.
    - Accept all, send to spam, or reject the email

# 2.4 DHCP

- Leases
    
    > DORA four steps of how a device gets a lease
    > 
    1. Discovery 
        - Find a DHCP server
        - The client (your PC) shouts, *"Is there a DHCP server out there? I need an IP!"*
    2. Offer
        - Get an offer
        - The DHCP server hears the shout and says, *"I have one! Here is `192.168.1.50` for you.*
    3. Request
        - Lock in the offer
        - The client says, *"I'll take it! Please officially assign `192.168.1.50` to me.*
    4. Acknowledgment (ACK)
        - DHCP server confirmation
        - The server says, *"Done! You have a lease for the next 24 hours. Enjoy!"*
- Reservations
    1. **DHCP Reservations (MAC Binding)**
        - This is a "Magic Trick" in networking. You can tell the DHCP server: *"Whenever you see the laptop with this specific **MAC Address** (Hardware ID), **ALWAYS** give it the IP `192.168.1.50`."*
        - **Why use this?** It’s like having a "Reserved" sign at a restaurant. The device gets the same IP address every time (like a Static IP), but you manage it automatically through the DHCP server instead of typing it in manually on the device.
- Scope
    1. A **Scope** is simply the **range** of IP addresses that the DHCP server is allowed to hand out.
        - *Example:* Your router might have a scope of `192.168.1.100` to `192.168.1.200`.
        - This means it has **101 addresses** available for guests, phones, and laptops.
- Exclusions
    1. Sometimes, you want to "carve out" a piece of the scope so the DHCP server **never** gives those numbers away.
        - *Example:* You might exclude `192.168.1.100` to `192.168.1.110` because you want to manually give those addresses to your office printers.

# 2.6 IPv4 and IPv6

- IPv4
    1. An IPv4 address consists of 32 bits
    2. IPv4 addresses are expressed with the use of Decimal numbers
    3. Private IP addresses
        - Assigned within a home or business network for internal communication
        - Cannot be routed over the public Internet and are only valid within the confines of a local network
        - Can be reused across different networks (i.e., they do not need to be unique globally)
    4. Private IP addresses Common Ranges
        - **10.0.0.0 - 10.255.255.255 (10.0.0.0/8)**  (Large corporations) - Class A range
        - **172.16.0.0 - 172.31.255.255 (172.16.0.0/12)** - Class B range
        - 192.168.0.0 - 192.168.255.255 (192.168.0.0/16) (Most home routers) - Class C range
    5. Public IP addresses
        - Assigned by ISPs to devices for communication over the Internet
        - Unique across the entire Internet, ensuring that devices can be identified and located globally
        - Used for devices that need to communicate directly with the Internet and are routable through the global internet infrastructure
    - IPv6
        1. An IPv6 address consists of 128 bits
        2. IPv6 addresses are expressed with the use of Hexadecimal numbers
        3. IPv6 was primarily developed to mitigate the issue of Address exhaustion
        4. **No more Private/Public split:** Every device can technically have its own unique global address.
        5. **Link-Local Address:** Every IPv6 device automatically gives itself an address starting with **`fe80::`**. This allows it to talk to other devices on the same local switch without a router or DHCP server.
    - Automatic Private IP Adresses (APIPA)
        1. APIPA allows a Windows host to self-configure an IPv4 address and subnet mask when a DHCP server is unavailable.
        2. APIPA uses the address block range from 169.254.0.0 to 169.254.255.255.
        3. APIPA-assigned addresses are valid only for communication within the network segment to which the host is connected.
        4. A host with an APIPA-assigned address cannot connect to the Internet.
    - Static IP addresses
        1. Provide a permanent address, essential for services requiring consistent reachability 
        2. Must be manually assigned or reserved through administrative tools, requiring more management
        3. Ideal for servers, network devices needing a stable address, and remote access applications 
    - Dynamic IP addresses
        1. Change periodically, making them unsuitable for hosting services that require a fixed address
        2. Assigned automatically by a DHCP server, minimizing user configuration
        3. Commonly used for consumer devices, prioritizing ease of use, security, and cost efficiency
    - Subnet mask
        1. a 32-bit number that divides 
        2. It identifies which part of an IP address belongs to the network and which part belongs to the host
        3. *Example:* `255.255.255.0` tells the PC that the first three numbers of the IP must match everyone else on the network.
    - Default Gateway
        1. A network device (router) that enables exchange of data between hosts residing in different subnets.

# 2.7 Network Type

- LAN - Local area network
    1. Local area network
        - Local is relative
    2. A building or group of buildings
        - High-speed connectivity
    3. Ethernet and 802.11 wireless
        - Any slower and it isn’t “local”
- WAN - Wide area network
    1. WAN - Wide area network
        - Spanning the globe
    2. Generally connects LANs across a distance
        - And generally much slower than the LAN
    3. Many different WAN technologies
        - Point-to-point serial, Multiprotocol Label Switching (MPLS), etc.
- PAN - Personal area network
    1. **Key Characteristics**
        - **Short Range:** Typically covers a radius of about **10 meters (30 feet)**.
        - Low Power: Because the devices are so close, they don't need high-powered transmitters. This saves battery life on mobile devices.
        - **Ad-hoc:** Devices often join and leave a PAN dynamically (like your headphones connecting to your phone as soon as you put them on).
    2. Common Technologies
        - Bluetooth: The most common PAN technology. It uses the 2.4 GHz frequency to link headsets, keyboards, mice, and game controllers
        - USB (Universal Serial Bus): Even a wired connection between your PC and your phone or a printer is technically a "Wired PAN.”
- MAN - Metropolitan Area Network
    1. Key Characteristics
        - Geographic Scope: Typically covers a city, a large town, or a large campus (usually a 5km to 50km radius).
        - Ownership: Often owned by a single large entity (like a city government or a university) or a service provider that rents the connection to businesses.
        - High Speed: Because it uses fiber optic cables to connect sites, it is much faster than a standard internet connection.
    2. Common Technologies
        - Metro Ethernet: Using standard Ethernet technology but over a massive scale to connect different parts of a city.
        - Fiber Optics: The backbone of most MANs, allowing data to travel between buildings at light speed.
        - Microwave/Radio Links: Sometimes used to connect buildings where digging trenches for cables is too difficult (like across a river or a busy highway).
- Storage area network (SAN)
    1.  Key Characteristics
        - Block-Level Access: Unlike a NAS (which handles files), a SAN handles "blocks" of data. This makes it much more efficient for databases and high-end applications like video editing or 3D rendering.
        - Redundancy: SANs are designed so that if one cable or one switch fails, the data keeps flowing.
        - High Performance: It uses specialized technology to ensure there is zero "lag" between the server and the hard drive.
    2. Common SAN Technologies
        - **Fibre Channel (FC):** A very expensive, very fast fiber optic technology dedicated specifically to storage. It requires special "Host Bus Adapters" (HBAs) instead of regular network cards.
        - **iSCSI (Internet Small Computer Systems Interface):** A way to run SAN commands over regular Ethernet cables. It’s cheaper than Fibre Channel and very popular in medium-sized businesses.
- Wireless local area network (WLAN)
    1. Key Characteristics
        - Standard: WLANs use the IEEE 802.11 standards, which we commonly call Wi-Fi.
        - Flexibility: The biggest advantage is mobility. You can move around the office or house without losing your connection.
        - Range: Typically covers a few hundred feet, though this can be blocked by walls, metal, or water.
    2. The Core Components
        - Wireless Access Point (WAP or AP): This is the central hub. It connects to the wired network and "broadcasts" the signal to the air.
        - Wireless Network Interface Card (NIC): Every device (your laptop, smartphone, or ROG Ally) has a small wireless radio and antenna inside it that allows it to talk to the Access Point.

# 3.4 RAID - Redundant Array of Independent Disks

- RAID 0
    1.  Requires a minimum of 2 drives to implement
    2.  Is also known as disk striping
    3.  Decreases reliability (failure of any disk in the array results in the loss of all data in the array)
    4.  Is suitable for systems where performance takes precedence over fault tolerance
- RAID 1
    1.  Requires at least 2 drives to implement 
    2. Is also referred to as disk mirroring
    3. Improves reliability by duplicating data on each drive (if one drive fails, data remains accessible) 
- RAID 5
    1.  Requires at least 3 drives to implement
    2. Offers both increased performance and fault tolerance (a single drive failure does not result in data loss; the array can rebuild the missing data) 
    3.  Is also known as disk striping with parity
- RAID 6
    1. Requires at least 4 drives to implement
    2. Offers increased performance and fault tolerance (up to 2 drive failures can be tolerated without data loss)
    3.  Is also known as disk striping with double parity
- RAID 10
    1. Requires a minimum of 4 drives to implement
    2. Offers increased performance and fault tolerance (the array can survive the failure of one drive in each mirrored pair) 
    3.  Is known as a stripe of mirrors, combining RAID 1 (mirroring) with RAID 0 (striping)

# 4.2 Cloud Computing

**Common Cloud Models:** 

- Private cloud
    - A cloud infrastructure that is exclusively used by a single organization
    - Organizations with strict compliance and security requirements would typically use a private cloud
- Public cloud
    - Available to everyone over the lnternet
    - shared across multiple organizations or tenants
- Hybrid cloud
    - A mix of public and private
    - Combines the benefits of private and public cloud deployment models
- Community cloud
    - Several organizations share the same resources
    - A cloud environment developed for universities conducting joint research projects
    - A shared cloud used by several government agencies
    - A cloud-based solution for public safety organizations with similar data handling policies

**LaaS, PaaS, SaaS:**

- Infrastructure as a service (LaaS)
    - Sometimes called Hardware as a Service (HaaS)
    - A cloud computing service model where clients, instead of buying hardware and software, access computing infrastructure as an outsourced service from suppliers who own and maintain all the necessary equipment and software
- Platform as as service (PaaS)
    - Gives users the benefits of using the cloud and the ability to customize their own development
    - A cloud computing service model would provide the best solution for a web developer intending to create a web app
- Software as a service (SaaS)
    - Allows end users to access their email, documents, and spreadsheets directly within their web browser
    - A cloud computing service model that provides users with remote access to applications over the Internet on a subscription
    

**Cloud characteristics:** 

- Shared resources vs Dedicated resources
    - Shared resources:
        - Refer to an arrangement where multiple customers use the same underlying physical infrastructure
        - Lower costs due to economies of scale
        - Possible performance degradation during high demand periods
    - Dedicated resources:
        - Refer to resources that are reserved for a single customer
        - Consistent and reliable performance
        - Higher, fixed costs regardless of resource use
        - Greater control and stronger data isolation
        - refer to private cloud
- Metered utilization
    - a billing model where customers are charged based on actual resource consumption.
        - Ingress: Cost to data entering the cloud
        - egress: Cost to data leaving cloud
- Elasticity
    - allocation adjusts automatically based on demand
    - Allows resources to scale up or down dynamically based on demand
    - minimizes the risk of having too many idle resources (over-provisioning) or too few resources during peak times (under-provisioning), leading to efficient resource management.
- Availability
    - Systems are always available
    - Redundancy provides availability
    - Ensuring services are accessible with minimal interruption
    - **Service Level Agreement (SLA):** 99.9 Uptime percentage that services are guaranteed to be operational.
- File synchronization
    - Information can be duplicated across cloud locations
    - Reflecting file edits made on one device across all other connected devices
- Multitenancy
    - Many different clients are using the same cloud infrastructure and applications completely separate
    - Enables several customers to share a single software deployment without accessing each other's data

# 5.1 Hardware Troubleshooting

# 5.2 Troubleshoot drive and RAID

- RAID LED Status Indicators
    - Green: Drive operating normally; data safe
    - Amber / Yellow: Warning or minor issue (slow reads /writes)
    - Red: Critical failure; possible failed drive or RAID disk error
    - Tip: Always verify LED meanings in the manufacturer's manual – codes can vary by model
- Grinding Noises
    - Indicates wear or misalignment of moving parts (read/ write heads, spindle motor)
    - Stop using the drive immediately & backup data if possible
    - Continued use can cause irreversible data loss
- Clicking Sounds
    - Signals the actuator arm or heads can't locate data sectors
    - Implies a near-total mechanical failure; backup & replace immediately
- Bootable Device Not Found
    - Common Causes:
        - Corrupted OS on boot drive
        - Failed RAID member or disk
        - BIOS/UEFI misconfiguration pointing to wrong drive
    - Action: Verify BIOS settings & RAID integrity
    
    ![image.png](image%2074.png)
    
- Data Loss I Corruption
    - Causes: Power loss, RAID sync failure, or physical disk issues
    - Symptoms:
        - Inaccessible or unreadable files
        - Corrupted documents or images
        - Error messages like "Drive not found" or 'Data integrity check failed”
    - Response: Use recovery tools & attempt RAlD rebuilds to minimize downtime
- RAID Failures
    - Single Drive Failure (RAID 1): Replace the failed drive immediately to restore redundancy
    - Multiple Drive Failure (RAID 5 / 6): Two failed drives in RAID 5 or three in RAID 6 may cause total data loss
    - Actions: Check LED indicators, listen fornoises, & attempt a controlled rebuild
- **Self-monitoring and Reporting Technology (S.M.A.R.T.) failure**
    - High temperatures, read/write errors, & bad sectors suggest imminent drive failure
    - Fix: Backup data immediately, replace the drive, & run diagnostic utilities
- **Extended Read / Write Times**
    - May signal bad sectors, degraded RAID arrays, or an overworked controller
    - Fix: Use disk management & S.M.A.R.T. tools to isolate & replace slow drives
- Low performance input/output operations per second (IOPS)
    - Caused by degraded disks, file fragmentation, or network bottlenecks
    - Fix :Check RAID health, defragment disks, & upgrade old drives or controllers
- Missing Drives in OS
    - Often due to loose cables, bad sectors, or misconfigured arrays.
    - Fix: Verify physical connections, RAID setup, & perform OS-level disk checks
- Array missing
    - usually indicates drive failures, controller issues, or improper shutdown, often rendering data inaccessible
    - Fix: Do not reinitialize or format the drives. Instead, re-seat drives, check cable connections, check BIOS/controller status
- Audible alarms
    - a security feature designed to alert administrators of a hardware fault.
